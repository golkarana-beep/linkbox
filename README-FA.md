# لینک‌باکس — نسخه GitHub Pages + Supabase

این نسخه برای انتشار عمومی طراحی شده است: بازدیدکنندگان لینک‌ها را می‌بینند؛ مدیریت داده‌ها نیازمند ورود مدیر است. داده‌ها در Supabase ذخیره می‌شوند و سایر دستگاه‌ها هر ۱۵ ثانیه تغییرات را بررسی می‌کنند.

## ۱) ساخت پروژه Supabase
1. به https://supabase.com بروید و حساب رایگان بسازید.
2. یک پروژه جدید ایجاد کنید و رمز دیتابیس را در جای امن نگه دارید.
3. در Project Settings → API (یا Connect) آدرس پروژه و کلید عمومی `publishable`/`anon` را بردارید.
4. فایل `config.js` در این بسته با آدرس پروژه و کلید عمومی‌ای که ارائه کردید تنظیم شده است. فقط کلید عمومی در آن قرار دارد؛ **service_role/secret key را هرگز در فایل سایت نگذارید**.
5. در `supabase-schema.sql` عبارت `PASTE_YOUR_REAL_AUTH_USER_UID_HERE` را با UID واقعی خود از Authentication → Users جایگزین کنید (هر دو بار)، سپس فایل را در SQL Editor اجرا کنید. بدون این کار، نوشتن برای مدیر فعال نمی‌شود.
6. به Authentication → Providers → Email بروید و ورود با ایمیل را فعال کنید.
7. در Authentication → Settings، ثبت‌نام عمومی کاربران را خاموش کنید؛ سیاست SQL نیز به‌طور مستقیم فقط UID مدیر مشخص‌شده را مجاز می‌کند.
8. در Authentication → Users، فقط حساب مدیر خودتان را بسازید. اگر ثبت‌نام بسته است، از گزینه افزودن کاربر در داشبورد استفاده کنید و یک رمز قوی تعیین کنید.

## ۲) انتشار در GitHub Pages
1. یک مخزن جدید در https://github.com/new بسازید.
2. فایل‌های `index.html`، `styles.css`، `app.js`، `config.js` و `supabase-schema.sql` را به ریشه مخزن اضافه کنید.
3. در مخزن بروید به Settings → Pages.
4. در Build and deployment گزینه Deploy from a branch را انتخاب کنید، شاخه `main` و پوشه `/ (root)` را انتخاب و Save کنید.
5. پس از پایان انتشار، آدرس GitHub Pages را باز کنید.

## ۳) ورود و استفاده
- همه بازدیدکنندگان صفحه را بدون ورود می‌بینند.
- دکمه «ورود مدیر» را بزنید و با ایمیل و رمز حساب Supabase وارد شوید.
- افزودن لینک و دسته‌بندی فقط برای مدیر فعال می‌شود. تغییرات به صورت خودکار در Supabase ذخیره می‌شوند.
- سایر دستگاه‌ها تغییرات ذخیره‌شده را حداکثر حدود ۱۵ ثانیه بعد دریافت می‌کنند.

## نکات مهم
- این نسخه از JSONBin و Master Key مرورگری استفاده نمی‌کند.
- کلید عمومی Supabase در فرانت‌اند قابل مشاهده است و این طبیعی است؛ امنیت باید با RLS و تنظیمات Authentication برقرار شود.
- سیاست SQL نوشتن را فقط برای UID مشخص‌شده مجاز می‌کند. ثبت‌نام عمومی را نیز خاموش نگه دارید.
- این نسخه داده‌های سایت را در یک ردیف JSON ذخیره می‌کند؛ برای سایت بزرگ با چند مدیر همزمان، ساختار جداول جداگانه مناسب‌تر است.
- اگر می‌خواهید تصویرهای آپلودشده از هارد هم روی همه دستگاه‌ها دیده شوند، بهتر است بعداً Supabase Storage را هم اضافه کنیم؛ base64های بزرگ در JSON می‌توانند حجم رکورد را زیاد کنند.
- پیش از مهاجرت، از نسخه فعلی در تنظیمات همگام‌سازی خروجی JSON بگیرید. اطلاعات LocalStorage قبلی خودکار به Supabase منتقل نمی‌شوند.
